#+TITLE: lnav — mode-agnostic bracket navigation and editing

*lnav* is a mode-agnostic Emacs package for moving through and editing
bracketed structures: parentheses, brackets, braces, quotes, and any
user-defined pairs.

Every pair is a *chunk* carrying four positions: before open, after
open, before close, after close.  Chunks nest.  TAB
jumps in and out of pairs (tabjumpout style), chunk navigation walks
the nesting, and editing commands wrap, strip, or rewrap delimiters.
Works in any major mode and integrates with evil (`il`/`al` text
objects) when present.

* Features

- TAB / backtab jump through brackets
- Chunk tree: each `()`, `[]`, `{}`, `""`, `''`, ... is a nestable chunk
- Jump to all four positions of a chunk (before/after its open/close)
- Descend / ascend nesting, next / previous chunk boundary
- Select chunk contents or chunk including delimiters
- Surround a region or chunk with any delimiter
- Slurp, barf, kill, transpose, raise, splice structural editing
- Full smartparens-style surface: hybrid kill, delete/copy/clone,
  convolute, absorb, emit, extract, split/join, swap, splice-killing,
  add-to-previous/next, select-next-thing
- Flash label jumping (flash.nvim style): chunks, chars, words, search
  (regex/fuzzy), multi-window, treesitter nodes
- Delete / change the enclosing pair (unwrap / rewrap)
- Auto-pair typing mode, strict balance mode, matching-pair highlight
- Optional evil integration: `il`, `al` text objects and surround keys
- Coexists with smartparens: edits use programmatic insert, so no
  double pairs

* Installation

Place `lnav.el` (and `lnav-evil.el` for evil bindings) on your
`load-path`:

#+begin_src emacs-lisp
  (add-to-list 'load-path "~/path/to/lnav")
  (require 'lnav)
  (global-lnav-mode 1)      ; or (lnav-mode 1) per buffer
#+end_src

`lnav-evil.el` is loaded automatically once evil is present; it is
optional and never required by the core.

* TAB navigation

Works in any major mode.  `lnav-jump-forward` on TAB, `lnav-jump-backward`
on backtab:

| Buffer   | Command        | Result  |
|----------+----------------+---------|
| `{|`     | TAB            | `{|}`   |
| `{|}`    | TAB            | `{}|`   |
| `|{}`    | TAB            | `{|}`   |
| `|{}`    | TAB TAB        | `{}|`   |
| `{}|`    | backtab        | `{|}`   |

When no pair is in scope, TAB falls back to a per-mode function
(default: indent, with org-table awareness).  Snippet frameworks
(yasnippet, tempel) take precedence over pair jumps.

* Chunk navigation

Each 1-char bracket pair is a chunk; chunks nest.  `il`-style editing
needs the four positions of a chunk, all reachable:

| Keys         | Command                     | Moves to                        |
|--------------+-----------------------------+---------------------------------|
| `C-c n`      | `lnav-next-chunk`           | next chunk boundary             |
| `C-c p`      | `lnav-previous-chunk`       | previous chunk boundary         |
| `C-c b`      | `lnav-jump-before-open`     | before opening delimiter        |
| `C-c a`      | `lnav-jump-after-open`      | after opening delimiter         |
| `C-c c`      | `lnav-jump-before-close`    | before closing delimiter        |
| `C-c d`      | `lnav-jump-after-close`     | after closing delimiter         |
| `C-c i`      | `lnav-chunk-in`             | first child chunk               |
| `C-c o`      | `lnav-chunk-out`            | parent chunk                    |
| `C-c s`      | `lnav-select-chunk`         | select chunk contents           |
| `C-c S`      | `lnav-select-chunk-around`  | select chunk incl. delimiters   |

Jump and select commands act on the *innermost chunk containing
point*.

* Editing

| Keys    | Command                     | Effect                                  |
|---------+-----------------------------+-----------------------------------------|
| `C-c w` | `lnav-surround`             | wrap region (or chunk) in a delimiter   |
| `C-c x` | `lnav-delete-enclosing-pair`| strip the enclosing pair's delimiters   |
| `C-c r` | `lnav-change-enclosing-pair`| replace the enclosing pair's delimiters |

- `lnav-surround` prompts for a delimiter.  With an active region it
  wraps the region; otherwise it wraps the contents of the chunk at
  point.  Enter `(` to get `(...)`, `"` to get `"..."`, or any string
  (multi-char works).
- `lnav-delete-enclosing-pair` removes the delimiters of the chunk at
  point, keeping the contents.  Point inside `(foo)` leaves `foo`.
- `lnav-change-enclosing-pair` rewraps, e.g. `(foo)` to `[foo]`.

These commands insert/delete programmatically, so smartparens and
electric-pair-mode never add or remove a second pair.

* Structural editing

slurp/barf/splice-style operations on the chunk at point.  Forms are
found with the buffer's syntax table (`forward-sexp`), so atoms and
chunks both work.

| Keys    | Command                     | Effect                                |
|---------+-----------------------------+---------------------------------------|
| `C-c >` | `lnav-slurp-forward`        | pull next form in:  `(a) b` -> `(a b)` |
| `C-c <` | `lnav-slurp-backward`       | pull previous form in: `a (b)` -> `(a b)` |
| `C-c ]` | `lnav-barf-forward`         | push last form out: `(a b) c` -> `(a) b c` |
| `C-c [` | `lnav-barf-backward`        | push first form out: `a (b c)` -> `a b (c)` |
| `C-c k` | `lnav-kill-sexp`            | kill chunk including delimiters       |
| `C-c t` | `lnav-transpose-sexp`       | swap chunk with next form: `(a) (b)` -> `(b) (a)` |
| `C-c R` | `lnav-raise-sexp`           | replace parent with chunk: `(a (b) c)` -> `(b)` |
| `C-c W` | `lnav-wrap-sexp`            | wrap chunk incl. delimiters: `(a)` -> `((a))` |
| `C-c f` | `lnav-forward-sexp`         | move to end of next form              |
| `C-c F` | `lnav-backward-sexp`        | move to start of previous form        |

`lnav-delete-enclosing-pair` (`C-c x`) doubles as splice: it removes
the current level's delimiters and keeps its contents.

Wrap convenience commands: `lnav-wrap-round`, `lnav-wrap-curly`,
`lnav-wrap-square`, `lnav-wrap-quote`.

* Full smartparens surface

Beyond slurp/barf/raise/transpose, lnav implements the rest of the
smartparens structural command set (in `lnav-structural.el`):

- `lnav-kill-hybrid-sexp` — kill content up to the closing delimiter
- `lnav-delete-sexp`, `lnav-backward-delete-sexp`, `lnav-copy-sexp`,
  `lnav-backward-copy-sexp`, `lnav-clone-sexp`
- `lnav-splice-sexp-killing-backward/forward/around`
- `lnav-convolute-sexp`, `lnav-swap-enclosing-sexp`
- `lnav-emit-sexp`, `lnav-extract-before-sexp`, `lnav-extract-after-sexp`
- `lnav-split-sexp`, `lnav-join-sexp`, `lnav-absorb-sexp`
- `lnav-add-to-previous-sexp`, `lnav-add-to-next-sexp`
- `lnav-change-inner`, `lnav-select-next-thing(-exchange)`
- Navigation: `lnav-next-sexp`, `lnav-previous-sexp`,
  `lnav-forward/backward-parallel-sexp`, `lnav-backward-up-sexp`,
  `lnav-beginning/end-of-sexp` and next/previous variants,
  `lnav-down-sexp`, `lnav-forward/backward-symbol`, `lnav-narrow-to-sexp`

* Flash navigation

Flash-style label jumping (flash.nvim inspired), native in lnav.

| Keys    | Command                     | Effect                                  |
|---------+-----------------------------+-----------------------------------------|
| `C-c z` | `lnav-flash-chunk`          | labels on every chunk opening; jump     |
| `C-c Z` | `lnav-flash-char`           | labels on occurrences of a character    |
| `C-c /` | `lnav-flash-search`         | labels on regexp matches                |
|         | `lnav-flash-fuzzy`          | labels on fuzzy subsequence matches     |
|         | `lnav-flash-word`           | labels on word starts                   |
|         | `lnav-flash-treesit`        | labels on treesit ancestor nodes        |

Flow: invoke, then press a label to jump (RET jumps to the first
match, ESC/C-g cancels).  When matches overflow the label alphabet,
labels become two keys — type the first, then the second.

Config: `lnav-flash-labels`, `lnav-flash-autojump`,
`lnav-flash-multi-window` (flash across all visible windows),
`lnav-flash-show-backdrop`.  Faces: `lnav-flash-label-face`,
`lnav-flash-match-face`, `lnav-flash-backdrop-face`.

* Typing, strict, and highlight

Optional modes, all off by default:

- `lnav-typing-mode` — auto-pairs open delimiters, skips an existing
  closing delimiter, deletes an empty pair on backspace, and wraps an
  active region when you type an opening delimiter.  Off by default
  so parinfer-rust users are unaffected.
- `lnav-strict-mode` — refuses deletions that would unbalance bracket
  pairs.
- `lnav-show-pair-mode` — highlights the matching delimiters of the
  chunk at point.

* Tags and cheat sheet

- `lnav-wrap-tag`, `lnav-rewrap-tag` — wrap the chunk at point in
  markup tags.
- `lnav-cheat-sheet` — buffer listing every command by group.

* Evil integration

Loaded when evil is available.  Text objects usable with any
operator:

- `il` — inside the chunk (excludes delimiters): `dil`, `cil`, `yal`...
- `al` — around the chunk (includes delimiters): `dal`, `val`...

Surround keys:

| Keys | Command                     |
|------+-----------------------------|
| `gs` | surround region (visual) or chunk (normal) |
| `gS` | delete enclosing pair       |
| `gC` | change enclosing pair       |
| `g(` / `g)` | slurp backward / forward |
| `g{` / `g}` | barf backward / forward |
| `gt` | transpose sexp             |
| `gK` | kill sexp                  |
| `gr` | raise sexp                 |
| `gw` | wrap whole sexp            |
| `gf` / `gb` | forward / backward sexp |

All bindings are rebindable.

* Defining your own pairs

#+begin_src emacs-lisp
  (lnav-add-pair "\\begin{" "\\end{")   ; LaTeX
  (lnav-add-pair "$" "$")               ; inline math
  (lnav-add-pair "**" "**")             ; markdown bold
#+end_src

Or customize `lnav-pairs` directly:

#+begin_src emacs-lisp
  (setq lnav-pairs '(("(" . ")") ("\\begin{" . "\\end{")))
#+end_src

Rules:
- Pairs whose open and close differ (`()`, `[]`, `{}`, ...) nest in
  the chunk tree.
- Pairs with equal open and close (`"`, `'`, `` ` ``, `$`, `**`) are
  non-nesting toggles: each occurrence alternates open/close at its
  bracket nesting level, matching vim `i"` semantics.  This is
  approximate — the apostrophe inside `"don't"` while a double quote
  is open may mis-pair.
- Multi-char pairs (`\begin{}`, `**`) participate in TAB jumps but not
  in the chunk tree.

* Configuration

| Variable                 | Default                 | Purpose                                |
|--------------------------+-------------------------+----------------------------------------|
| `lnav-pairs`             | `()[]{}` `""` `''` `` ` `` | registered pairs                  |
| `lnav-fallback-alist`    | default indent fallback | per-mode TAB fallback                  |
| `lnav-excluded-modes`    | nil                     | modes where `lnav-mode` is disabled    |
| `lnav-enable-backward`   | t                       | enable backtab jumps                   |
| `lnav-scan-distance`     | 32                      | chars to scan when matching multi-char pairs |
| `lnav-flash-labels`      | home-row alphabet       | label alphabet for flash                     |
| `lnav-flash-autojump`    | nil                     | jump when a single match remains             |
| `lnav-flash-multi-window`| nil                     | flash across visible windows                 |

Per-mode fallback:

#+begin_src emacs-lisp
  (lnav-set-fallback #'org-cycle 'org-mode)
#+end_src

* Limitations

- Chunk parsing is regex/scan based, not syntax-aware: quotes in
  strings and apostrophes may mis-pair (see above).
- The chunk tree rescans the buffer on each navigation command — fine
  for code-scale buffers, slow for multi-megabyte logs.
- Unmatched brackets never error; the chunk keeps its open positions
  and a nil close.
